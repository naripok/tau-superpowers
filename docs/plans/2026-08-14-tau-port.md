# Port pi-superpowers to Tau — Execution Plan

> This is the coordination checklist for fresh-context agents. Update this file as work advances: change `[ ]` to `[x]`, add the commit hash, and record deviations under **Handoff notes**. Do not edit files owned by another in-progress step.

## Goal

Turn this repository from a Pi package into a Tau-compatible collection of Agent Skills plus a Python Tau extension that delegates single, parallel, and chained work to isolated `tau` subprocesses.

## Repository findings at plan creation

> This section records the pre-port baseline used to scope the work. Its Pi paths, commands, and implementation descriptions are historical findings, not current usage instructions; completed-step handoffs and the living spec describe the repository now.

- `skills/` contains 14 Agent Skills and supporting prompt/reference/example files. Their `SKILL.md` frontmatter already matches Tau's basic Agent Skills format, but several files contain Pi paths, Pi tool names, `Task({...})` examples, and `TodoWrite` assumptions.
- Tau discovers project skills from `.tau/skills/` or `.agents/skills/`, not the current top-level `skills/` package declaration. Installation/layout must therefore change or be generated/documented.
- `extensions/superpowers-subagent/` is a TypeScript Pi extension. It depends on Pi's TypeScript APIs, TypeBox, and Pi TUI components, discovers `~/.pi/agent/agents` and `.pi/agents`, and launches `pi --mode json -p --no-session --no-skills`.
- Tau extensions are Python modules exposing `setup(tau: ExtensionAPI)`. Tools use `tau_agent.tools.AgentTool`; project extensions live in `.tau/extensions/` and require trust plus `--project-extensions`, while explicit testing can use `tau -e PATH`.
- Tau 0.3.9 supports `--mode json`, `--provider`, `--model`, `--cwd`, `--append-system-prompt`, `--no-extensions`, and explicit `-e`. It does **not** expose Pi's `--no-session`, `--no-skills`, or `--tools` flags. Tau JSON emits lifecycle events including `message_end` with portable assistant messages.
- Tau model selection separates `--provider PROVIDER` and `--model MODEL`; the Pi-style combined model string needs an explicit compatibility decision and tests.
- The current living spec and historical design artifacts describe Pi behavior and must be updated after the implementation contract is settled.

## Coordination rules

1. Execute steps in numerical order unless a step explicitly says it may run in parallel.
2. One agent owns each step and its listed files. Do not opportunistically edit later-step files.
3. Start by reading this entire plan, `git status`, relevant Tau docs, and all files listed for the step.
4. Preserve unrelated user changes. Do not reset, clean, amend, or rewrite another agent's commits.
5. Each step ends with focused checks and one commit. Record the commit and notes below.
6. If Tau's public API cannot support a requirement, stop and document the gap rather than reaching into private session/Textual internals.
7. Use the real Tau extension runtime for integration tests (`tau -e ...`), not imports alone.
